分工书要求本周产出「Demo 页面骨架 + 工作流截图存档」。存档已完，剩三件：

### 第 1 件｜出契约文档草案（2 小时，今天）

我起草，另外两人只做确认。只定三件事：

- **判定引擎输出字段**：名字、类型、含义、示例值
- **前端一次请求带什么、返回什么**
- **文书需要哪些字段**

现在能写死的字段（以平台实际配置为准）：

| 字段 | 类型 | 含义 |
|---|---|---|
| verdict | String | HIT 构成 / MISS 不构成 / PENDING 待核实 / NA 不适用 |
| stage | String | need_industry / describe / ask / hit / miss / na |
| render | String | 给用户看的文本，**前端原样输出，一个字不改** |
| ask_more | String | 还剩几项要问（平台是 String，不是 Integer） |
| hits / pending / na / need_ask / ask_batch / checked / facts_used | — | 待平台补齐后再写进契约 |

请求侧：`query`（必填）+ `session_id`（1~32 位小写字母数字中划线，多轮必须同一个）。

## 四、三个我现在就要定的技术决定

### 决定 1：replay 模式从第一天就做

验收标准第 2 条要求「断网或额度耗尽有降级说明」，风险表里「演示翻车」影响标「极高」。
做法：`MODE=live|replay` 开关，把 Demo 六个分支（need_industry / describe / ask / hit / miss / na）的真实响应各存一份 JSON。
断网切 replay，演示照样走完，且存的是真实响应，和线上一致。这份缓存同时是评测脚本的离线基线，一举两得。

### 决定 2：SSE 解析做成独立适配层

平台返回流式，别把流解析写进页面。单独一层 `api/` 把 SSE 拼成完整对象再交给前端，前端只认结构化字段。
这样将来换渠道、加缓存、做 replay 都只改一层。

### 决定 3：依据链先做兜底渲染

若条款明细字段一直没补齐，就从 `render` 文本里正则抠条款号（`第十一条 第（十）项`）先渲染出「条款原文」入口。
等结构化字段到位，换成直接渲染，页面结构不用改。
